# Агентский план: адаптивный MMQ/cuBLAS для Qwen3.8 на CMP 50HX

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Собрать и испытать версию llama.cpp, которая оставляет MMQ для decode и небольших матриц, но проверяет cuBLAS на крупных prefill-матрицах; принять её только при воспроизводимом выигрыше без скрытой регрессии текущего пятислотового сервиса.

**Architecture:** Частный форк `verybigbadboy/llama.cpp` от чистого `b7d4d853a6ccf2b71012570348e0d7aab22798c0`. Один минимальный runtime-переключатель в `ggml_cuda_should_use_mmq`, выключенный по умолчанию. Сборка на CT200, пакет рядом с существующим на `192.168.50.9`, одна транзакция A/B через восстановительный runner, сырые строки и решение «оставить/отклонить». **Не брать локальный HEAD `d7878eb6`: в нём аварийный FA tile64.**

**Tech Stack:** C++/CUDA 12.8 `sm_75`, CMake/Ninja, NCCL, `llama-server`, `test-backend-ops`, Python stdlib `harness/bench_request.py`, `harness/test_harness.py`.

## Global Constraints

- Стенд `192.168.50.9` — тестовый; его llama-сервис можно останавливать в рамках A/B, но не оставлять остановленным. Сборки/пакеты — **только CT200**, не 50.9. Не перезаписывать рабочий бинарник, кэш и unit; пакет версионировать и хранить rollback.
- Модель и компоненты во всех плечах: `Qwen3.8-27B-UD-Q4_K_XL.gguf`, mmproj Q8_0, 3×20-ГиБ GPU0–2 Gen2 x8, KV q8_0/q8_0, FA on, `--spec-type none`, `--parallel 5`, `--ctx-size 327680`, `--kv-unified-per-slot 65536`, `-b 2048 -ub 512`, отдельный экспериментальный каталог `--cache-disk`. Сохранять все остальные аргументы действующего `profile/current-selected.service`.
- Не сравнивать числа разных кампаний как A/B. Сначала свежий нейтральный контроль и якорь штатного бинарника. `llama-bench` для распределения по GPU недействителен; нужен `llama-server` + запросы с проверкой размещения. `short` prefill шумен — смотреть TTFT/медиану и классы, не один выброс.
- PPL на 2048 токенах проверяет только этот корпус/длину; long-context и vision проверять отдельно. FA tile64, `row`, FORCE_MMQ, «разлочка compute», повышение power limit и смена драйвера не входят в эту задачу.
- До любого изменения read-only снимок (`systemctl show`, хэши, `/slots`, сервисы на GPU3, PCIe, Xid с временными метками). Восстановить **тот же** unit, а не доверять устаревшему rollback-файлу. Останавливать тест при новом Xid, SIGILL, потере линка/карты, OOM, расхождении корректности. Старые Xid после прошлой кампании не считать новым сбоем; сохранять исходный kernel-journal cursor и сравнивать новые события с ним.
- Результат этой инструкции — либо новая проверенная версионированная сборка и таблица A/B, либо честно документированный отрицательный результат и восстановленный сервис. Не заявлять успех по факту успешной компиляции.
